## Product change

- Storage supplies one static migration instruction for `migration-required`, naming the exact versioned package command rather than relying on the unversioned npm latest release.
- The loader returns its existing delegating fetch without constructing a manager or refresh queue. Local generative calls receive Google's 412 `FAILED_PRECONDITION` envelope, identifying explicit offline conversion of the old pool as the prerequisite for local serving; unrelated fetches retain normal passthrough and caller cancellation. Request-time authority is still checked first, so an approved vault can serve without reading the dormant native login.
- Account target resolution no longer treats `migration-required` as permission to use the pool. Account-state sidebar publication and quota/tier producers leave the unavailable local target untouched; they do not fabricate an empty manager or change defaults.

No core migration/store primitive, embedding, dependency, manifest, lockfile, updater policy, existing native helper, `.motor/hosts`, or documentation outside this evidence directory is changed.
