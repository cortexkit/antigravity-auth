# Codebase Structure

A Bun monorepo of three published TypeScript packages and one private test package. This file is a map; to find a specific symbol or file, search the code rather than this document. [ARCHITECTURE.md](ARCHITECTURE.md) explains how the pieces work together.

## Workspace

```text
packages/
  core/        @cortexkit/antigravity-auth-core: accounts, OAuth, transport, transforms, quota, vault source, model catalog
  opencode/    @cortexkit/opencode-antigravity-auth: OpenCode 1 and 2 server plugins, TUI renderers, CLI
  pi/          @cortexkit/pi-antigravity-auth: Pi extension
  e2e-tests/   private: mock-server flows, OpenCode 2 Docker and native harnesses
scripts/       release, version sync, prepush gate, native-inert gate, dev symlink
test/          test preload (test/setup.ts), repo-wide guards, Windows job scripts
tools/common-auth-build/  pinned common-auth archive and the private TUI compiler inputs
test-fixtures/ captured agy CLI requests and model metadata, used by wire-shape tests
docs/          dead-code inventory
research/      earlier library-adoption and CI investigations; not shipped
```

## `packages/core/src`

- `index.ts`: the public barrel. Subpath exports are listed in `package.json`.
- `account-manager.ts`, `account-selector.ts`, `rotation.ts`: account selection, rate limits, health and token-bucket scoring, backoff.
- `account-repository*.ts`, `account-migration.ts`, `account-storage.ts`: the lease-backed account store, its migrations and relocation, and the legacy pool-file format.
- `antigravity/oauth.ts`, `auth.ts`, `project.ts`: OAuth with PKCE, token expiry, project discovery.
- `agy-transport.ts`, `pre-response-deadline.ts`, `fetch-timeout.ts`: the raw HTTP/1.1 sender and its deadlines.
- `agy-request-metadata.ts`, `transform/`: request identity and payload transforms (Claude, Gemini, cross-model cleanup, model resolution).
- `model-registry.ts`: the model catalog, quota groups and retired routes.
- `quota-manager.ts`, `quota-presentation.ts`: quota reads and their display projection.
- `vault-account-source.ts`, `vault-enrollment-authority.ts`, `vault-provider-state.ts`, `vault-family.ts`: vault and host-mode accounts and authority.
- `antigravity-command-menu.ts`: the shared `/antigravity` menu.
- `common-auth-runtime.ts`, `common-auth-embedded/`: lazy loaders for the embedded common-auth modules. The embedded tree is generated; don't edit it by hand.

## `packages/opencode`

- `index.ts`: the package root, the OpenCode 1 plugin. `src/server.ts` is the `./server` entry: one default export that is an OpenCode 2 plugin and also carries the OpenCode 1 `server` function. `server.js` and `tui.js` at the package root forward OpenCode 2's directory loader to the same entries.
- `src/plugin/index.ts`: the OpenCode 1 composition root (`createAntigravityPlugin`).
- `src/plugin/auth-loader.ts`, `fetch-interceptor.ts`: OpenCode 1 request entry.
- `src/plugin/shared/request-services.ts`: the request engine used by both OpenCode lines. Siblings in `shared/` hold credentials, cancellation, vault routing and the vault menu.
- `src/plugin/request.ts`, `request-helpers.ts`, `core/streaming/`: request preparation and the response stream transformer.
- `src/plugin/vault-custody.ts`, `ga-shared-vault-custody.ts`, `vault-activation.ts`: vault and host-mode custody, and the OpenCode 1 vault login.
- `src/plugin/ga-location-services.ts`: per-location local and vault services for OpenCode 2.
- `src/plugin/config/`: the `antigravity.json` schema (`schema.ts`), loader and writer.
- `src/ga/server/`: the OpenCode 2 plugin: request hook, loopback bridge, retry hook (`index.ts`), login methods (`auth.ts`, `pool-login.ts`).
- `src/ga/rpc/protocol.ts`, `src/ga/tui/host-ga.tsx`: OpenCode 2 TUI protocol and renderer.
- `src/tui.tsx`, `src/tui/`: the OpenCode 1 sidebar and menus, the shared sidebar frame, and `tui/entry.mjs`, the `./tui` export.
- `src/rpc/`, `src/sidebar-state.ts`: the OpenCode 1 status server and the sidebar snapshot.
- `src/runtime-paths.ts`, `runtime-layout.ts`, `version-fence.ts`, `vault-folder.ts`, `process-heartbeat.ts`: where files live, the one-time file moves, and their fences.
- `src/cli.ts`, `src/setup.ts`: the `antigravity-auth` CLI (`setup`, `login`, `list`, `quota`, `init`, `migrate`, `rollback`, `store relocate`).
- `scripts/build-tui.ts`, `scripts/embed-common-auth.ts`, `scripts/smoke-tui-pack-install.ts`: renderer build and import-graph policy, embedding check, packed-install smoke.
- `docs/`: user and contributor guides (configuration, vault, OpenCode 2, troubleshooting, sidebar contract).

## `packages/pi/src`

- `index.ts`: the extension entry. It synchronizes the `google` slot, then registers the provider and `/antigravity`.
- `stream.ts`, `convert.ts`: Pi's request conversion and stream.
- `vault-source.ts`, `vault-setup.ts`, `commands.ts`: vault and host mode, and the menu.

## Generated and tracked output

- **Tracked, generated by scripts:** both `common-auth-embedded/` trees (`embed-common-auth.ts`), and `packages/opencode/assets/antigravity.schema.json` (`script/build-schema.ts`).
- **Ignored build output:** `dist/`, and the four renderer trees `packages/opencode/src/tui-raw/`, `tui-compiled/`, `tui-ga-raw/` and `tui-ga-compiled/`.
- **Agent working folders:** `.cortexkit/` is ignored. Only `.cortexkit/WORKER.md`, the guide for worker agents, is tracked.

## Where to add a change

- **A model or quota group:** `packages/core/src/model-registry.ts`, then its transform in `transform/` if the wire differs.
- **A request rule:** `packages/opencode/src/plugin/request.ts` or the engine, with tests on both OpenCode lines.
- **A setting:** `packages/opencode/src/plugin/config/schema.ts`, then regenerate the JSON schema with `build:schema`.
- **A menu action:** `packages/core/src/antigravity-command-menu.ts`. Host-only sections go in `packages/opencode/src/plugin/commands.ts` or `packages/pi/src/commands.ts`.
- **A sidebar field:** `sidebar-state.ts` and `sidebar-projection.ts`, plus `docs/sidebar-contract.md`. No credentials, project ids or fingerprints.
- **A test that writes to disk with fsync, rename, chmod or locks:** list it in `test/support/disk-test-files.ts`.
